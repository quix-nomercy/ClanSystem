# ClanSystem

Clan plugin for SCP: Secret Laboratory servers running EXILED 9.14.2.

Players create clans, invite others, and every clan member wears the clan tag in front of their name in the player list:

```
[JOKER] quix
```

The commands work from the server console, the Remote Admin panel, the player console and the Server-Specific Settings menu, and every text is editable in `config.yml`.

## Features

- `create`, `delete`, `invite`, `info`, plus `accept`, `decline`, `leave`, `kick` and `list`.
- Clan tag written into the player display name, with configurable format, color and upper case.
- Invites have to be accepted by the target player, and they expire.
- Server-Specific Settings menu with a clan name field, a player picker, a status box and buttons for every action.
- No database. Clans are stored in one JSON file inside the EXILED config folder.
- Everything is configurable: command names and aliases, clan rules, limits, tag format, menu labels and every message.

## Requirements

- Server on SCP: Secret Laboratory 14.x with EXILED 9.14.2.

## Installation

1. Copy `ClanSystem.dll` into the EXILED `Plugins` folder of the server (`~/.config/EXILED/Plugins` on Linux).
2. Start the server. EXILED creates `config.yml` for the plugin, the clan file is created on the first clan.
3. Edit the config, then restart the server or reload the plugin.

The default configuration already works. The permissions are open on purpose: every player can use the clan commands until you turn on `command.require_permission` or one of the `rules.only_leader_can_*` options.

## Commands

The root command is `clan` (`clans` as alias). Names and aliases of every sub-command are configurable.

| Action | Syntax | Notes |
| --- | --- | --- |
| Create | `clan create <name> [owner]` | Players use their own name, the server console has to pass `owner`. |
| Delete | `clan delete [name]` | Without a name it deletes the clan of the sender. |
| Invite | `clan invite <player> [clan]` | Without a clan name the sender's clan is used. |
| Info | `clan info [name]` | Without a name it shows the sender's clan. |
| Accept | `clan accept [clan]` | Player only, accepts the oldest invite when no name is given. |
| Decline | `clan decline [clan]` | Player only. |
| Leave | `clan leave` | Player only, the leader has to delete the clan. |
| Kick | `clan kick <player> [clan]` | Without a clan name the sender's clan is used. |
| List | `clan list` | Shows every clan with leader and member count. |

`<player>` accepts a player id, a part of the nickname or a full user id.

The server console and Remote Admin use the plain command (`clan create Rail`). The game only forwards console commands that start with a dot, so players type `.clan create Rail` in their own console. The Server-Specific Settings menu needs no command at all.

## Server-Specific Settings

The menu is registered by `ServerSpecificSettingsSync` and merged with the settings of other plugins, so nothing of another plugin is removed.

- Group header (`CLAN`).
- Clan name field, used by create, delete, invite, info, accept and decline.
- Player picker with the online players, used by invite and kick. It refreshes when players join or leave, and the refresh waits until the tab is closed so nothing moves while you use it.
- Status box, shows your clan, your role, the member count and pending invites.
- Buttons: Create clan, Delete clan, Invite player, Clan info, Accept invite, Decline invite, Leave clan, Kick member.

The menu can be disabled with `menu.enabled`, and the setting ids start at `menu.base_setting_id` (twelve ids are used).

## Clan tag in the player list

The N player list shows the display name of a player, and ClanSystem writes the clan tag into it.

- Default format: `[{clan}] {name}`, with `{clan}` upper cased, so `Rail` becomes `[RAIL] Ali Volt1x`.
- The tag is applied when a player joins, after every clan change, on round start and whenever the display name changes. It is removed when the plugin is disabled.
- The game marks custom display names with a brown `*` and shows the real nickname in parentheses inside Remote Admin, for example `[RAIL] Ali Volt1x* (Ali Volt1x)`. That marker comes from the game itself and cannot be removed.
- The game cuts display names to 48 characters. ClanSystem cuts the tag to `tag.display_name_limit` instead of losing the player name, and writes a warning to the server console when a tag is too long, so keep `rules.max_name_length` small.
- Set `tag.show: false` to keep the display names untouched.

## Configuration

`config.yml` is generated by EXILED and contains all sections:

- `command`: root command, sub-command names and aliases, permission switches.
- `rules`: clan name length, name pattern, blocked names, member limit, clan limit per player, leader-only switches.
- `tag`: show switch, format, upper case, color, length limit.
- `invites`: invite lifetime, invite limit per player, online-only invites.
- `menu`: Server-Specific Settings labels, button texts and hints, reply switches, announcements.
- `messages`: every message the plugin can send, with `{placeholders}` for names, clan names and counters.

`CONFIG-EXAMPLE.yml` in this repository shows the generated file with the default values and a short note for every option.

## Data

Clans are stored in `Configs/ClanSystem/clans.json` (`data_file` changes the path). The file is written after every change.

```json
{
  "Version": 1,
  "Clans": [
    {
      "Name": "Joker",
      "LeaderId": "76561198000000000@steam",
      "Members": ["76561198000000000@steam", "76561198000000001@steam"],
      "Names": {
        "76561198000000000@steam": "quix"
      },
      "CreatedUtc": "2026-01-01T12:00:00Z"
    }
  ]
}
```

Members are stored by user id and keep the last known nickname for the info and list output. Deleting the file removes every clan.

## Notes

- Invites are kept in memory and are lost on a restart. Clan membership is not.
- No database, no webhooks, no HTTP calls.
- The plugin does not touch badges, ranks or other plugins' display names; it only sets the display name of its own clan members.
